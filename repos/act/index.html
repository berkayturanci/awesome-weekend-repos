The CI loop that wastes your time.

You write, you commit, you push, you wait — red. Again. Twenty commits later, green. act breaks that loop.

push → wait → fail → repeat

One command runs your workflow locally.

The act command reads your .github/workflows/, pulls Docker images, and runs the workflow locally. Same environment, same variables, your machine.

act → reads workflows → runs in Docker

It matches GitHub's environment exactly.

It mirrors the environment variables, secrets, and filesystem that GitHub provides. If it passes here, it passes there.

env vars · secrets · fs → matches GitHub

Run just one job, or the whole workflow.

Run a single job instead of the whole workflow. Or trigger a specific event — pull_request, push, schedule. You control what gets tested.

act -j test · act pull_request · act push
